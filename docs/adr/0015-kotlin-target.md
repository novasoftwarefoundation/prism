# 0015: The Kotlin target: tokens and components in Jetpack Compose, on Maven Central

Status: proposed, 2026-11-23

## Context

The Android app (Flux 10537065009) is a native Next shell like the iOS app, in Jetpack Compose with Material 3. It copies Prism's colors, type and radii by hand into one theme file of its own, because Prism has no Android target. That is the drift [ADR 0001](0001-design-format.md) rejects ("Tokens only, components hand-written per platform"), which [ADR 0009](0009-swift-target.md) removed for iOS. ADR 0001 planned "Kotlin (later): the same values for Compose" and already makes every family bind `android:`.

Compose has a look for a control in two places. Material 3's controls take their colors as public classes (`ButtonColors`, `CheckboxColors`, `TextFieldColors`) and a shape, a border, padding and an `interactionSource`; their sizes, their text style and their ripple are their own. Compose's foundation is under them: `Modifier.clickable`, `toggleable` and `selectable` give a control its role, focus, keyboard and indication; `BasicTextField` gives a text field its editing, IME, selection and accessibility and takes a `TextFieldDecorator` for its look; `InteractionSource` says whether it is pressed, hovered or focused. Prism's look sets sizes Material fixes, so most components are Prism composables on foundation, as Material's own are.

An Android app gets a library from a Maven repository. Melle decided on 23 November: "yes, Maven Central from the prism repo". There is no mirror repository as for Swift: Prism's CI builds `targets/kotlin/` and publishes it on a version tag, as it publishes the npm packages.

## Decision

1. **A file target, `kotlin`.** `Prism.Generator.Kotlin` writes `targets/kotlin/`: `settings.gradle.kts` and `build.gradle.kts`, and in `src/main/kotlin/<package>/` the tokens (`Tokens.kt`), the types a look is made of (`Look.kt`), one file per component and the input metadata ([ADR 0012](0012-semantic-input-metadata.md), `InputMetadata.kt`). The files are committed, carry the `Prism.Generator.Header` line (`//`), `mix prism.gen --check` covers them, and they are reviewed in Prism's pull requests. The design names the library: `kotlin package: "org.novasoftwarefoundation.prism", name: "Prism", artifact: "prism-compose"` in `Prism.Design.Tokens`, its Kotlin package and Android namespace, the prefix of its types (`PrismButton`, `Prism.Colors`) and its Maven artifact. It is one Android library: the Android Gradle plugin 9.5.2, Kotlin 2.4.21 with the Compose compiler plugin, the Compose BOM 2026.11.01 (Compose 1.13, Material 3 1.5.0), compileSdk 37.1 (Compose 1.13 needs it), minSdk 23, JDK 17, Kotlin's explicit API mode and every warning an error. It is compiled for Kotlin 2.2 (`languageVersion` and `apiVersion` 2.2, the standard library 2.2.20), Compose 1.13's own floor, so an app on Kotlin 2.2 or later reads it; compiled for 2.4, it would need Kotlin 2.3 in the app, since a compiler reads metadata at most one version ahead. Gradle compiles every source below `src/main/kotlin`, so the target names it as a source folder (`source_folders/1`): `mix prism.gen` removes a generated source anywhere below it that no target writes now, such as a renamed package's, and `--check` fails on one. `gradle.properties` (the Maven group and the POM), `README.md` and `.gitignore` in `targets/kotlin/` are hand-written.

2. **The tokens and all components, each in Compose's own form** (`Prism.Generator.Kotlin.Components`). Where Material 3 has a public extension point that keeps the control's behavior and lets Prism's look be drawn, the component uses it; where Material fixes what the design sets, it is a Prism composable on Compose's foundation, which keeps the behavior:

   | Component | Kotlin | Why not Material's |
   |---|---|---|
   | `button` | `PrismButton(onClick, variant = PrismButtonVariant.Primary, tone = …, loading = saving) { Text("Save") }`, on `Modifier.clickable` with `Role.Button` and the app's `LocalIndication` | `Button` takes `ButtonColors`, a shape, a border, `contentPadding` and an `interactionSource`, but has a minimum size of 58×40 dp (`ButtonDefaults.MinWidth`, `MinHeight`), its own label style, and always draws Material's ripple (its `Surface` doesn't read `LocalIndication`). Prism's link, text and icon buttons are smaller, and its pressed look moves the label and adds an inset shadow. |
   | `spinner` | `PrismSpinner(variant = …, size = PrismSpinnerSize.Size20, progress = 0.4f)`, a `Canvas` with `progressSemantics` | `CircularProgressIndicator`'s indeterminate arc grows and shrinks (Material's motion), where Prism's is a quarter ring that turns. |
   | `checkbox` | `PrismCheckbox(checked, onCheckedChange)`, on `Modifier.toggleable` with `Role.Checkbox` | `Checkbox` takes `CheckboxColors`, but its box is a fixed 20 dp with a 2 dp radius. |
   | `text_field`, `text_area` | `PrismTextField(state, invalid = …, prefix = { Text("€") })`, `PrismTextArea(state)`: `BasicTextField` on a `TextFieldState`, with a decorator that draws the box, the prefix ([ADR 0010](0010-text-field-prefix.md)) and the placeholder | `OutlinedTextField` has a minimum height of 56 dp and a floating label, and its prefix sits inside its padding; `OutlinedTextFieldDefaults.DecorationBox` is public, but its prefix has the same place, so it can't fill the height with its own background and line. |
   | `select` | `PrismSelect(expanded, onExpandedChange, label = { Text(choice) }) { Option(selected, onClick) { Text("…") } }`, on Material's `ExposedDropdownMenuBox`, its list in `ExposedDropdownMenu` with the listbox's look | Material's (stable since 1.5): it opens and places the menu, with its anchor's semantics. The field and the options are Prism's. |
   | `radio_group`, `radio` | `PrismRadioGroup { PrismRadio(checked, onClick) { Text("Yes") } }`, on `Modifier.selectableGroup` and `Modifier.selectable` with `Role.RadioButton` | `RadioButton` is a fixed 20 dp ring. |
   | `image_picker` | `PrismImagePicker(shape = …, preview = { Image(…) }, button = { PrismButton(…) { … } })` ([ADR 0011](0011-image-picker.md)) | none in Material. |
   | `field`, `tag`, `message_bar`, `step_indicator` | a composable each: `PrismField(label = { Text("Email") }) { PrismTextField(state) }`, `PrismTag(tone = PrismTagTone.Success) { Text("Done") }` | Material's chips are interactive (`onClick` is required); `Snackbar` is transient and Material has no banner. |

   The target knows every component of the design (ADR 0001, decision 3.2) and their parts by name, as the Swift target does, and fails generation for one it doesn't know.

3. **The API, by the same rules as the Swift and React components, in Compose's order.** What a component can't do without comes first (`onClick`, `checked`, a text field's `state`), then `modifier`, then the design's choices, `enabled`, the parts the app fills, `interactionSource`, and the content last.
   - **Each axis is an enum class** of the design's values (`PrismButtonVariant`, `PrismSpinnerSize`), with the design's default; a default without a look of its own is a case too, an alias a property of the companion object. Cases are UpperCamelCase, as Compose names its values (`Role.Button`); a variant named by a number has its axis's name in front (`Size16`). An axis without a default is nullable, `null` by default.
   - **Flags and the states the app sets are parameters** (`padded`, `loading`, `invalid`), a value a `Float?`: a spinner's progress from 0 to 1, as Compose's progress indicators take it, which its looks turn into the design's 0 to 100. A checkbox's or a radio's `checked` is the control's value, as Compose's own controls take it.
   - **States Compose knows come from Compose:** pressed, hovered and focused from the `interactionSource` (`collectIsPressedAsState()`), a field's focus from its control's (`onFocusChanged`), a select's while its menu is open or its field has focus; disabled from `enabled`, Compose's parameter, which every control takes. A select's list's and options' states are the options' own, in `Option`, not the select's parameters, as on iOS.
   - **Parts the app fills are slots:** a button's `icon` and `iconSide` (`PrismSide.Start` or `End`, for a part with `position:`), a text field's `prefix`, a field's `label` and `errorMessage`, a select's `icon`. While a slot is filled, the component has its look with that part.

4. **Looks as data, laid over each other as on the web.** Each component has `PrismComponentLooks`: its own look and each part's for one choice of variants, flags, parts, values and states, as `PrismLook` values, which the composable draws and an app can read for a composable of its own (`Modifier.prismBox(look)`, `PrismText(look) { … }`, `PrismLookBox(look) { … }`). The generated code lays each node's look, with its `android:` binding in place of the shared properties, over the others in the order the web's CSS makes them win. That order is no longer the Swift target's: `Prism.Generator.Swift.Looks` becomes `Prism.Generator.Looks`, which takes the platform (`:ios` or `:android`), so both native targets follow one rule, [ADR 0008](0008-app-state-over-interaction.md)'s included: a focused invalid text field keeps its warning border on Android as on the web and iOS. The Swift files don't change.

5. **Mechanics are the target's**, as the web's are in its CSS. A button is `Modifier.clickable` with the button role and the app's indication: Material's ripple under a `MaterialTheme`, or whatever the app's theme gives `LocalIndication` (ADR 0001 names ripple as Android's mechanic), drawn by the box over its background inside its shape, as Material clips its own controls' (a checkbox's too); it shows its spinner over its label while loading. A spinner draws its ring (a quarter of it, at a quarter's opacity around) and turns once per its rotation, or with a progress value its track and an arc from the top in the value's stroke, and has progress semantics for TalkBack. A checkbox draws its check mark. An outer shadow is `Modifier.dropShadow` and an inset one `Modifier.innerShadow`, with CSS's blur and spread. A border is inside the box, so padding and size are CSS's border box; a border on some sides draws a line on each. An outline is drawn outside the box at its offset. Material's `Text` and `Icon` in a component take its text style and color from `LocalTextStyle` and `LocalContentColor`, which the component sets. A field, a text field, a select and a message bar take the width they are given, as the web's block elements do. A look's colors and opacity animate over its transition; a move in the same update happens at once, as Compose lays out, so no `.geometryGroup()` is needed. Lengths are dp, rem times 16; a percentage is only a radius from 50% (a capsule) or a stroke. Sides are start and end, so they follow the text's direction.

6. **Type and font scaling.** Type comes only from the typography tokens and the components' typography pairs. A typography's size and line height are sp, so both follow the user's font size, Android 14's nonlinear curve to 200% included; Compose keeps an sp line height in proportion to its text. Padding and other lengths stay dp, as Android's guidance says. A line is as high as the typography's line height, with the text in its middle (`LineHeightStyle(Center, Trim.None)`), as on the web. Android never lays a line shorter than its font's own height, though: where the line height is less than that (a button's 18 on 18 sp, about 21 dp in Roboto), the line is the font's height, so such a box is a few dp taller than on the web. A look with text has its height and its size as the least it takes (`heightIn(min = …)`, `sizeIn(…)`), so a text field, a select, a message bar and a step indicator grow with their text at 200% instead of cutting it off. On the web a fixed height lets the text overflow; on Android it would be drawn outside its box.

7. **Fonts.** Both families are the system font on Android (ADR 0001: `FontFamily.Default`, Roboto), so the library bundles no fonts. The Android scale is still Nunito's weights ([ADR 0013](0013-emphasis-per-family.md)); measuring Roboto against Nunito, as ADR 0013 measured SF Pro, is a change to the design's `android:` scale and nothing else. A family bound to a named font is the device's font of that name (`DeviceFontFamilyName`) at each weight of its scale, the system font where the device lacks it; bundling a named font's faces in the library (`res/font`, which takes TTF or OTF, not the web's WOFF2) is a later change of the target, as on iOS (ADR 0009, decision 7).

8. **Delivery: Maven Central, from Prism's own CI, at Prism's version.** The library is `org.novasoftwarefoundation:prism-compose:X.Y.Z` on Maven Central, so an app needs only `mavenCentral()` and no token: `implementation("org.novasoftwarefoundation:prism-compose:0.6.0")`. The namespace `org.novasoftwarefoundation` is verified in the Central Publisher Portal with a DNS TXT record on `novasoftwarefoundation.org`, the organization's domain ([namespace registration](https://central.sonatype.org/register/namespace/)); `io.github.<organization>` is not available to an organization.
   - **The build never meets the secrets.** Gradle, the Android Gradle plugin, Kotlin's and their plugins (some 190 build-script artifacts, resolved at release time) are code that could read whatever is in their environment. So, as the Webflow bundle is built apart from the job that publishes ([ADR 0014](0014-webflow-designer-extension.md)), the release builds the Kotlin bundle in a job with read access and no secret, `maven-bundle`, and the job that holds the secrets, `maven-central`, takes the bundle as data and runs no build: no Gradle, no JDK, no Android SDK. `release-workflow.test.mjs` fails when a job that reads a secret (in its own environment, a step's, its container's or services', or the workflow's) runs Gradle, sets up a JDK, Gradle or the Android SDK, or builds the bundle.
   - **The bundle signed is the bundle built.** Other jobs of the run can upload artifacts too (the Webflow job's npm packages run beside `maven-bundle`), so a name alone doesn't say which job made one. `maven-bundle` gives the uploaded artifact's id and the bundle's digest (`--digest`: the sha256 of each file's path and sha256) as its outputs; `maven-central` downloads the artifact by that id, and the script stops before it checks the bundle or imports the key when the bundle's digest isn't that output. `release-workflow.test.mjs` fails when the download is by name or either output or the digest's hand-over is gone; `kotlin-release.test.mjs` runs the script on a bundle swapped with checksums of its own, and fails when it gets to signing.
   - **`.github/kotlin-release.sh --bundle X.Y.Z <dir>`**, in `maven-bundle` (and in CI), builds the release variant at that version into a Maven repository of its own (`publishToMavenLocal`) and makes the bundle Central requires ([requirements](https://central.sonatype.org/publish/requirements/)): the AAR, its POM and Gradle module file, the sources and javadoc jars, each with an `.md5` and a `.sha1`. The POM has the name, description, URL, MIT license, developer, and SCM pointing at the Prism repository. `--check X.Y.Z <dir>` checks a bundle: exactly the files of `.github/maven-files.txt`, each as its checksums say, and the POM's fields.
   - **`.github/kotlin-release.sh vX.Y.Z <dir>`**, in `maven-central`, checks first: the four secrets are set, Prism's tag is checked out and clean, and `design/mix.exs` is at the version; then it checks the bundle as `--check` does, signs each file with an `.asc` from the signing key (gpg), and uploads the bundle through the Central Publisher Portal's API ([Publisher API](https://central.sonatype.org/publish/publish-portal-api/)) with `publishingType=AUTOMATIC` (curl), so Central publishes it once it validates, and waits until the deployment is `PUBLISHED` or `FAILED`. A version Central already has is not uploaded again: the script compares Central's POM with the bundle's, so a rerun is safe. Central never changes or removes a published version ([immutability](https://central.sonatype.org/publish/requirements/immutability/)): a broken release is followed by a patch release.
   - **`release.yml`** runs `maven-central` on a version tag, after the npm packages and the Swift package and after `maven-bundle`, in a job of its own whose GitHub token can only read, so a failure there leaves the other releases as they are. It reads four repository secrets: `MAVEN_CENTRAL_USERNAME` and `MAVEN_CENTRAL_PASSWORD` (the Portal user token's two parts) and `MAVEN_SIGNING_KEY` (the ASCII-armored secret key) and `MAVEN_SIGNING_KEY_PASSWORD` (its passphrase). The key is RSA 4096, signing only, fingerprint `24270AF8F9E30AD3EDF7A0B0F9156907F9CCAC8D`, on `keyserver.ubuntu.com`. Central offers no trusted publishing (OIDC) as npm does, so the token is a stored secret.
   - A release candidate (`vX.Y.Z-rc.N`) is published as the version `X.Y.Z-rc.N`: Maven has no dist-tags, and Gradle and Maven order it before `X.Y.Z`. It stays on Central, as every version does.

9. **Checks.** In `generator/`, the two example designs' libraries are reviewed fixtures (`generator/test/fixtures/kotlin/components/`, a component of every kind, and `…/design/`, a token of every kind), and Elixir tests cover the build, the names, the tokens, the looks' order, the states, the slots, the values, the input metadata and the errors, and that every line is within 100 columns. One CI job, `kotlin` on Ubuntu, pins its toolchain (JDK 17, Gradle 9.9.2, the Android 37.1 platform and build tools 36.0.0), and builds Prism's library and both fixtures with every Kotlin warning an error and explicit API mode. It runs `design/test/compose/`, a Gradle project that is an app on Kotlin 2.2, the oldest the library is compiled for, so its checks and the READMEs' examples (`ReadmeSamples.kt`) compile as such an app does. It renders every Prism component that holds text on the JVM (Robolectric with Android's native graphics, so text has its real size, on SDK 34, the first with nonlinear font scaling), at 100% and at 200% font size, and fails when the text doesn't grow, wraps, or is taller than its box lets it be; it checks that a button's and a checkbox's indication stays inside their rounded shape, and reads the input metadata from what JSON parsers give (`500.0` from Gson or Moshi). That is worth its minute, as `design/test/swiftui/` is for iOS: it found that a step indicator's fixed size cut a two-digit step off at 200%. It needs no emulator; Paparazzi's screenshots would add pixels to review for a question a layout answers. Finally the job builds the release's bundle and checks it, with the release's own `--bundle` and `--check`. `design/test/kotlin_test.exs` checks the committed library, its coordinates and its POM properties. Nothing Prism-specific is in `generator/`; CI's check for it stays.

## Alternatives

| Option | Why not |
|---|---|
| Values only, a theme file per app (today's) | Each app writes the pressed, disabled and loading looks again; the drift ADR 0001 rejects. |
| Material's components, styled through their colors and shapes | Material fixes what the design sets: a button's 58×40 minimum and ripple, a checkbox's and a radio's 20 dp, a text field's 56 dp and its prefix's place. Material's select is used where it fixes nothing the design sets. |
| A `MaterialTheme` (`ColorScheme`, `Typography`, `Shapes`) generated from the tokens | Material's roles (`primary`, `onSurface`, `labelLarge`) are not Prism's names, and a theme still leaves each component's look to Material. An app can map Prism's tokens into its theme for its own Material components. |
| Resolve each combination at generation time into a table | As for Swift: laying the nodes' looks over each other at run time, in the web's order, keeps the code the size of the design. |
| A mirror repository, `prism-kotlin`, read with a Gradle source dependency or a submodule and `includeBuild` | The app would build Prism's source with its own Android Gradle plugin, Kotlin and Compose versions. Gradle's source dependencies have no user-guide page and were last described as incubating ([2018](https://blog.gradle.org/introducing-source-dependencies)); a composite build shares no plugins or repositories with the app ([composite builds](https://docs.gradle.org/current/userguide/composite_builds.html)). |
| JitPack | It builds on a third party's service the first time a version is asked for, signs nothing, and lets a version be rebuilt for seven days ([FAQ](https://docs.jitpack.io/faq/)). |
| GitHub Packages | Reading a public Maven package still needs a personal access token (classic) in every app and CI that builds it ([Gradle registry](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-gradle-registry)). |
| A static Maven repository on GitHub Pages | No token, but immutability, signing and availability would be Prism's to guarantee, and GitHub's Pages limits rule out commercial use ([limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)). |
| A community Gradle plugin for Central (vanniktech, JReleaser, nmcp) | Central supports none of them ([Gradle](https://central.sonatype.org/publish/publish-portal-gradle/)), and signing in Gradle puts the key where the build runs; the Publisher API is a single upload and a status request, which a script of Prism's does with `gpg`, `openssl` and `curl`, apart from the build. |
| One release job that builds, signs and uploads | The build's third-party code would run with the signing key and the Central token in its environment. |
| Compiled for Kotlin 2.4 only | An app would need Kotlin 2.3 or later, a floor of Prism's own, above Compose's. |
| A Gradle wrapper in `targets/kotlin/` | An app gets the published library, not its build; CI pins one Gradle, as it pins one Xcode. |
| A rendering test with Paparazzi on layoutlib, or on an emulator | Paparazzi 2 needs Java 21 and screenshots to review; an emulator needs minutes and KVM. The question, whether text fits its box at 200%, is a layout's, which Robolectric answers. |

## Consequences

- An Android app gets Prism's components from the design, with the same numbers as the web and iOS: it depends on `org.novasoftwarefoundation:prism-compose` at the release's version and deletes its theme file's copy of Prism's values. Material's own components in the app keep the app's theme.
- Every release publishes the library to Maven Central at Prism's version, after the npm packages and the Swift package. Until the first release the job has not run: its signing and upload are tested only by that release.
- A new kind of component needs its Compose form in `Prism.Generator.Kotlin.Components`; a new variant, part or state of a known component needs only the design.
- A focused invalid text field keeps its warning border on Android too ([ADR 0008](0008-app-state-over-interaction.md)); the look layering is one module for both native targets.
- Text whose line height is less than its font's own height is a few dp taller on Android than on the web; a box with such text (a button) is that much taller.
- Measuring Roboto's weights against Nunito, and bundling named fonts, are changes to the design's `android:` binding and the target's fonts, not to the components.
